### 1. Как проектирате CI/CD pipeline за React приложение, който осигурява бързи цикли на обратна връзка и надеждни внедрявания?

- **CI:** Lint → модулни тестове → компилация
- **CD:** внедряване във preview среда (напр. Vercel/Netlify) → изпълнение на E2E тестове → промотиране към staging/production
- Използвайте **GitHub Actions**, **CircleCI** или **GitLab CI**.

```yaml
# Пример за GitHub Actions
jobs:
  build-test:
    steps:
      - run: npm ci
      - run: npm run lint && npm test
  deploy:
    steps:
      - run: npm run build
      - run: npm run deploy:staging
```

### 2. Как подхождате към автоматизирането на внедряването на React приложение в множество среди (напр. dev, staging, prod)?

- Използвайте **конфигурация според средата** (`.env.dev`, `.env.staging`).
- Използвайте клонове или тагове (напр. `main → prod`, `develop → dev`).
- Скриптовете за внедряване прочитат контекста на средата динамично.

```bash

if [ "$ENV" == "staging" ]; then
  npm run deploy:staging
fi

```

### 3. Как интегрирате автоматизирани тестове (модулни, интеграционни, E2E) в CI/CD pipeline за React проект?

- **Модулни тестове:** Jest
- **Интеграционни:** React Testing Library
- **E2E:** Cypress или Playwright (без GUI в CI)

```yaml
steps:
  - run: npm test -- --coverage
  - run: npx cypress run
```

### 4. Каква е стратегията ви за връщане към предишна версия в CI/CD pipeline, ако внедряването в продукционна среда се провали?

- Използвайте **неизменяеми внедрявания** и **Git тагове** или **артефакти на версията**.
- Съхранявайте последната известна добра компилация и автоматизирайте връщането към нея:

```bash

aws s3 cp s3://backups/last-good-build ./ && npm run deploy

```

<br />

### 5. Как оптимизирате CI/CD pipeline, за да намалите времето за компилация на голяма React кодова база?

- Активирайте **инкрементални компилации** чрез TurboRepo или Nx
- **Кеширайте node_modules** и **артефактите от компилацията**
- Изпълнявайте задачите паралелно:

```yaml
- uses: actions/cache@v3
  with:
    path: node_modules
```

### 6. Как подхождате към защитата на CI/CD pipeline за React приложение?

- Редовно сменяйте и **криптирайте тайните** (използвайте GitHub Actions Secrets, Vault и др.).
- **Ограничете достъпа за запис** до основните клонове.
- Използвайте **подписани commit-и** и проверки на зависимостите (напр. `npm audit`).

### 11. Как проектирате система за мониторинг на React приложение в продукционна среда, която проследява производителността и грешките?

- **Мониторинг от клиента:** Sentry, LogRocket, Datadog RUM
- **Проследяване на грешки:** try/catch и логване чрез граници за грешки
- **Производителност:** изпращайте отчети чрез Web Vitals API

<br />

### 12. Как подхождате към мониторинга на Core Web Vitals (напр. LCP, CLS, FID) в React приложение след внедряване?

- Използвайте пакета [`web-vitals`](https://github.com/GoogleChrome/web-vitals), за да изпращате метрики към backend или доставчик на анализи:

```

import { onCLS, onFID, onLCP } from 'web-vitals';
onCLS(sendToAnalytics); onLCP(sendToAnalytics); onFID(sendToAnalytics);

```

### 14. Каква е стратегията ви за мониторинг на латентността и наличността на API в React приложение, зависещо от backend?

- Използвайте API за измерване на времето във frontend (`performance.now()`).
- Добавяйте заглавки за проследяване (напр. `x-request-id`).
- Докладвайте забавянията:

```

const start = performance.now();
fetch('/api/data').finally(() => {
  const duration = performance.now() - start;
  if (duration > 1000) logSlowAPI('/api/data', duration);
});

```

### 16. Как подхождате към логването в React приложение и как го интегрирате с инструментите за мониторинг?

- Използвайте **абстракция на console**:

```jsx
export const log = (msg) => {
  if (process.env.NODE_ENV === "production") {
    sendToLoggingService(msg);
  } else {
    console.log(msg);
  }
};
```

- Интегрирайте с **Sentry breadcrumbs** или **Datadog logs**.

### 17. Как реализирате разпределено проследяване в React приложение с backend от microservices?

- Добавяйте заглавки за проследяване от backend.
- Използвайте **OpenTelemetry** или **Datadog RUM**.
- Предавайте correlation ID:

```jsx
fetch("/api", {
  headers: { "x-trace-id": currentTraceId },
});
```

### 18. Какъв е процесът ви за мониторинг на използването на ресурси (напр. CPU, памет) в React приложение, внедрено в serverless платформа?

- Използвайте вградените инструменти на платформата (напр. Vercel Analytics).
- При нужда докладвайте използването на паметта от страна на клиента:

```

if (performance.memory) {
  log(performance.memory.usedJSHeapSize);
}

```
