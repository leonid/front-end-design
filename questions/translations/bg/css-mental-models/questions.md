### 1. Как си представяте CSS Box Model и влиянието му върху решенията за оформление в приложение на React?

**CSS Box Model** определя как се оразмеряват и разполагат елементите:

```css
Total size = content + padding + border + margin
```

В React третирам компонентите като **контейнери за оформление** или **блокове със съдържание**, а разбирането на box model е от ключово значение за:

- **Последователност на отстоянията** (напр. избягване на сливане на полетата)
- **Предвидимо оразмеряване** с `box-sizing: border-box`

Избягване на грешки с преливане във вложени структури.

Пример:

```css
* {
  box-sizing: border-box;
}
```

Така padding и border не влияят неочаквано на ширината и височината.

### 2. Какъв е мисловният ви модел за управление на специфичността и наследяването на CSS в мащабен проект на React?

Следвам принципа **„първо ниска специфичност“**:

- Използвам **стилове, ограничени до компонент** (CSS Modules или CSS-in-JS), за да намаля конфликтите на глобално ниво по отношение на специфичността.
- Предпочитам **селектори с един клас**.
- Избягвам прекалено уточнени селектори (`div.btn.primary`), които правят заместванията крехки.

Пример с CSS Modules:

```css
/* Button.module.css */
.button {
  color: white;
}
```

В React:

```jsx
<button className={styles.button}>Submit</button>
```

Също така ограничавам употребата на `!important` и избягвам наследяване на критични свойства като тези за оформление, като вместо това избирам **изрични декларации**.

### 3. Как разбирате връзката между моделите за оформление в CSS (напр. Flexbox, Grid) и йерархиите от компоненти в React?

Съобразявам **отговорностите за оформление с границите на компонентите**:

- **Flexbox**: използва се в рамките на компонент за едноизмерно подравняване (напр. ленти за навигация, карти).
- **CSS Grid**: използва се на по-високо ниво за двуизмерно оформление (напр. обвивки на страници, табла).

Дърво на компонентите в React ↔ модел за оформление в CSS:

- Компонент контейнер = система за оформление (Grid/Flex)
- Крайни компоненти = блокове със съдържание (позиционирани в оформлението на родителя)

Пример:

```jsx
<GridLayout>
  <Sidebar />
  <MainContent />
</GridLayout>
```

Това насърчава **разделянето на логиката за оформление и съдържание**.

### 4. Как подхождате към моделирането на адаптивен дизайн в CSS за приложение на React?

Предпочитам **CSS с подход „първо за мобилни устройства“**, помощни токени и системи за дизайн.

Подход:

- Използвам медийни заявки `@media` или **помощни средства за медийни заявки в CSS-in-JS**.
- Структурирам точките на прекъсване чрез **тема или конфигурационен обект**.
- Предпочитам **относителни единици** (`rem`, `%`) за мащабируемост.

Пример (Styled Components):

```jsx
const Card = styled.div`
  padding: 1rem;
  @media (min-width: 768px) {
    padding: 2rem;
  }
`;
```

При мащабиране използвам **дизайн токени** и **централизирана система за оформление**, за да поддържам последователност.

### 5. Как разсъждавате за производителността на CSS (напр. преизчисляване на оформлението и повторно изчертаване) в контекста на повторното изобразяване в React?

Основен принцип: **свеждане до минимум на ненужните промени в оформлението**.

Аз:

- Избягвам честото задействане на скъпи CSS свойства (като `width`, `top`).
- Предпочитам `transform` и `opacity` за анимации — те не задействат преизчисляване на оформлението.
- Използвам debounce при четене и запис в DOM при взаимодействие с оформлението (напр. обработчици на преоразмеряване).

В React:

- Избягвам ненужни промени в DOM по време на изобразяване.
- Използвам `memo`, `useCallback`, за да не предизвиквам скъпи преизчислявания на оформлението чрез актуализации на DOM.

### 6. Какъв е мисловният ви модел за обхвата на CSS в приложение на React (напр. CSS Modules, Styled Components)?

Третирам всеки компонент като **граница на стиловете**. Ограничаването на обхвата на CSS предотвратява изтичане и нежелани замествания на стилове.

**CSS Modules**:

- Просто, бързо ограничаване на обхвата чрез класове.
- Подходящи за традиционни работни процеси с CSS.

  **Styled Components / Emotion**:

- Напълно капсулирани стилове
- Съвместно разполагане на стиловете и логиката, с използване на props за динамично стилизиране.

Пример:

```jsx
const Button = styled.button`
  background: ${({ primary }) => (primary ? "blue" : "gray")};
`;
```

За големи приложения често използвам **CSS Modules + помощни класове** (напр. Tailwind) за балансиран подход.

### 7. Как проектирате CSS архитектура, която поддържа теми (напр. тъмен режим) в приложение на React?

Проектирам теми с помощта на **собствени CSS свойства** и **контекст/доставчик на тема**.

CSS:

```css
:root {
  --bg-color: white;
}
[data-theme="dark"] {
  --bg-color: #121212;
}
```

React:

```jsx
<body data-theme={theme}>...</body>
```

Използвайте **превключвател на тема**, за да актуализирате `data-theme`, и управлявайте състоянието на темата чрез глобален контекст или `localStorage`.

Алтернатива със Styled Components:

```jsx
<ThemeProvider theme={lightTheme}>...</ThemeProvider>
```

### 8. Как разбирате развитието на CSS от препроцесори (напр. Sass) към съвременни стандарти (напр. нативно влагане)?

Sass въведе:

- Влагане
- Променливи
- Миксини

Днес **нативният CSS** и **CSS-in-JS** покриват повечето случаи на употреба:

- Нативни променливи и влагане (в съвременните браузъри)
- По-добро **композиране** чрез помощни класове и **дизайн токени**

Съвременният CSS се фокусира върху **модулност**, **оперативна съвместимост** и **производителност**. Преминах от Sass към:

- **CSS Modules** за структура
- **Tailwind** или **CSS-in-JS** за стилизиране чрез помощни средства
- **Нативни възможности**, когато поддръжката от браузърите го позволява

### 9. Как подхождате към моделирането на CSS анимации и преходи в приложение на React?

Разделям анимациите на:

- **Преходи на интерфейса, управлявани от състояние** (модални прозорци, падащи менюта) → използвам `Framer Motion` или `React Transition Group`.
- **Статични анимации** → използвам `@keyframes` или `transition` в CSS.

Пример (Framer Motion):

```jsx
<motion.div
  animate={{ opacity: 1 }}
  initial={{ opacity: 0 }}
  exit={{ opacity: 0 }}
/>
```

Предпочитам **CSS преходи** за прости ефекти (по-малко натоварване) и **анимации, управлявани от JS**, когато взаимодействието или състоянието са сложни.

### 10. Как проектирате CSS система, която поддържа последователност между браузърите в приложение на React?

Подход:

- Използвайте **CSS нулирания** (напр. Normalize.css или `@tailwind base`)
- Предпочитайте **стандартизирани свойства с широка поддръжка**
- Използвайте **PostCSS/autoprefixer** за префикси на доставчиците
- Тествайте в различни среди (Chrome, Safari, Firefox)

Резервни варианти:

```css
display: grid;
display: -ms-grid; /* резервен вариант за по-стар IE */
```

Когато е необходимо, добавям полифили или осигурявам постепенно деградиране и разчитам на **съвременни CSS инструменти** за съвместимост между браузърите.
