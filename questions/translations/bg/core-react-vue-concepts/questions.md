### 1. Какво представлява Virtual DOM и как React го използва за повишаване на производителността?

Virtual DOM (VDOM) е леко, в паметта създадено представяне на реалния DOM. React го използва, за да оптимизира актуализациите и рендирането.

Когато състоянието или пропсите се променят:

- React рендира нов VDOM.
- Сравнява новия VDOM със предишния (използвайки **diffing алгоритъм**).
- Изчислява минималния набор от промени (patches).
- След това актуализира реалния DOM ефективно по **батчен** начин.

Това намалява директните манипулации с DOM, които са скъпи, и повишава производителността.

### 2. Обяснете разликата между функционални и класови компоненти в React.

| Аспект | Класов компонент | Функционален компонент |
| ------ | ---------------- | --------------------- |
| Синтаксис | ES6 класове | Обикновени JS функции |
| Състояние | `this.state` | `useState` Hook |
| Животен цикъл | `componentDidMount`, etc. | `useEffect` |
| `this` контекст | Задължителен | Не се използва |

<br />

### 3. Какво представляват React Hooks? Обяснете `useState`, `useEffect` и `useContext` с примери.

Hooks позволяват на функционалните компоненти да управляват **състоянието**, страничните ефекти и контекста — функции, които преди бяха налични само в класовите компоненти.

- **`useState`**: Управлява локално състояние.
- **`useEffect`**: Обработва странични ефекти (извличане на данни, абонаменти).
- **`useContext`**: Достъп до стойности на контекста.

<br />

### 4. Как React обработва методите на жизнения цикъл на компонентите във функционални компоненти?

Функционалните компоненти използват **Hooks**, за да имитират поведението на жизнения цикъл:

| Метод на жизнения цикъл на класа | Еквивалент на Hook |
| -------------------------------- | ------------------ |
| `componentDidMount` | `useEffect(..., [])` |
| `componentDidUpdate` | `useEffect(..., [deps])` |
| `componentWillUnmount` | `return () => {}` в `useEffect` |

<br />

### 5. Какво е значението на ключовете (`keys`) в React списъците и какво се случва, ако не ги използвате правилно?

**Keys** помагат на React да идентифицира кои елементи в списък са се променили, добавили или премахнали. Те трябва да са **уникални и стабилни**.

Ако използвате индекси като ключове или ги пропуснете:

- React може да повторно използва компоненти неправилно.
- Това може да причини грешки в рендирането или лоша производителност.

### 6. Какви са основните разлики между React.js и Vue.js по отношение на архитектурата на компонентите и реактивността?

| Функция | React | Vue |
| ------- | ----- | --- |
| Език | JSX + JS | HTML шаблони + JS |
| Реактивност | Непроменяемо състояние, ръчно актуализиране | Реактивни refs и proxies |
| Модел на компоненти | Функционално-ориентиран с Hooks | Options API / Composition API |
| Двупосочна връзка | Еднопосочна | Двупосочна чрез `v-model` |
| Управление на състоянието | Context, Redux, Zustand | Vuex, Pinia |

React е по-**неопределен** (свобода, гъвкавост), докато Vue предлага по-**пълен изначално** разработчешки опит.

### 7. Как решавате дали да използвате React.js или Vue.js за нов проект? Какви фактори влияят на избора?

**Фактори:**

- **Опит на екипа** (React е по-често срещан в enterprise среда).
- **Нужди на екосистемата** (напр. Next.js срещу Nuxt).
- **Сложност на проекта** (Vue е по-подходящ за малки до средни приложения).
- **Предпочитания за инструменти** (React: гъвкав, Vue: по-интегриран).
- **Поддръжка на общността** и **пазарът на труда** (React има по-широко разпространение).

**Правило за практиката:**

- За големи, дългосрочни и силно персонализирани потребителски интерфейси → React.
- За приложения, които трябва да се пуснат бързо, или екипи с по-малка дълбочина в JS → Vue.

### 8. Как бихте мигрирали наследено React приложение от класови компоненти към функционални компоненти с Hooks?

**Стъпка по стъпка:**

1. Започнете с изолирани, нискорискови компоненти.
2. Заменете `state` с `useState`.
3. Заменете методите на жизнения цикъл с `useEffect`.
4. Обработете връзванията, като премахнете `this`.
5. Мигрирайте потребителите на контекста с `useContext`.

### 9. Какво представляват Higher-Order Components (HOCs)? Дайте пример за случай, в който сте ги използвали.

HOC е **функция, която приема компонент и връща нов компонент** с подобрено поведение. Това е модел за повторно използване на код.

**Случай на използване:**
Използвал съм HOCs, за да:

- Вмъквам глобална логика (напр. logging, error boundaries).
- Добавям проверки за автентикация към маршрути.
- Свързвам компоненти с Redux (напр. `connect()`).

<br />

### 10. Как обработвате сложна композиция на компоненти в React.js или Vue.js, за да избегнете силно свързан код?

**Стратегии:**

- Използвайте **compound components** за споделян контекст и поведение, подобно на слотове.
- Прилагайте **render props** или **custom Hooks** за повторно използване на логика.
- Разделяйте UI и логика (smart/dumb component pattern).
- Избягвайте prop drilling чрез **context** или **provide/inject** в Vue.

### 11. Какво е React Reconciliation и как работи под капака?

Reconciliation е процесът, който React използва, за да актуализира DOM при промяна на състоянието или пропсите на компонент.

Стъпки:

1. Промяна на състоянието задейства **ново VDOM дърво**.
2. React **diff-ва** него с предишното дърво с помощта на **хеуристичен алгоритъм** (O(n)).
3. Идентифицира минималните промени и актуализира реалния DOM.

**Ключови оптимизации:**

- Използва **keys** за откриване на промени в списък.
- Приема, че компоненти със същия тип ще произведат подобен изход.
- Използва архитектурата **Fiber** за асинхронно рендиране и приоритизиране.

Това прави актуализациите предсказуеми и ефективни, особено в големи потребителски интерфейси.
