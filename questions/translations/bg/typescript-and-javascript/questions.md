### 1. Как работи цикълът на събитията в JavaScript и как влияе на визуализирането и актуализирането на състоянието в React?

Цикълът на събитията позволява на JavaScript (с една нишка) да обработва **асинхронни операции** чрез **стек от извиквания**, **опашка със задачи (макрозадачи)** и **опашка с микрозадачи**.

В React:

- `setState` се **групира и изпълнява асинхронно**.
- Актуализациите на състоянието и визуализирането се случват **след изпразване на текущия стек от извиквания** (поставят се в опашка като микрозадачи или макрозадачи според контекста).
- Разбирането на това помага да се предотвратят състезателни условия и да се гарантира предвидимо актуализиране на UI.

### 2. Какъв мисловен модел използвате, за да разбирате затварянията в JavaScript и да ги прилагате ефективно в React приложение?

Затварянето е функция, която **запазва достъпа си до лексикалния обхват**, дори когато бъде извикана извън него.

В React:

- Полезни са за **мемоизирани обратни извиквания** или за управление на **капсулирано състояние** в персонализирани hooks.

С ефектите трябва да се борави внимателно, за да се избегнат проблеми с **остаряло състояние**, причинени от затваряния.

### 3. Как обяснявате прототипното наследяване в JavaScript и по какво се различава от класическото наследяване?

Прототипното наследяване свързва обекти чрез **веригата `[[Prototype]]`**, което позволява споделяне на свойства.

За разлика от класическото наследяване:

- JS предпочита **делегиране между обекти вместо йерархии от класове**.
- То е по-**динамично и гъвкаво**, което добре се съчетава с **шаблоните за композиция** в React.

### 4. Какво е значението на ключовата дума `this` в JavaScript и как управлявате свързването ѝ в React компонентите?

`this` се отнася до **контекста на изпълнение**. В класовите компоненти на React `this` често се отнася до **екземпляра на компонента**.

В класовите компоненти:

`this.handleClick = this.handleClick.bind(this);`

Във функционалните компоненти:

- Избягвайте `this` изцяло, като използвате hooks и стрелкови функции.
- Стрелковите функции **свързват `this` лексикално**.

### 5. Как еднонишковият характер на JavaScript влияе на подхода ви към скъпите изчислителни задачи в React приложение?

Тъй като JS работи на **една нишка**, тежките задачи **блокират UI**.

Стратегии:

- Използвайте **Web Workers** за прехвърляне на задачи с интензивни изчисления.
- **Използвайте debounce/throttle** за входни данни.
- Използвайте **`requestIdleCallback`** или `setTimeout`, за да отложите работата.
- Поддържайте компонентите **чисти и бързи при визуализиране**.

### 6. Как проектирате надежден работен поток с async/await в React приложение за обработка на няколко API извиквания?

Използвайте `async/await` вътре в `useEffect`, обвийте го в `try/catch` и по избор използвайте `Promise.all`.

### 7. Каква е разликата между promise-ите и async/await под капака и как оптимизирате употребата им в React?

- **Promise-ите** представят асинхронни стойности; `then` свързва обратни извиквания във верига.
- `async/await` е **синтактична захар** върху promise-ите, която подобрява четимостта и отстраняването на грешки.

Оптимизации:

- Избягвайте вложени `await` в цикли (използвайте `Promise.all`).
- Мемоизирайте асинхронните функции с `useCallback`.
- Винаги **почиствайте ресурсите** в асинхронните ефекти, за да избегнете състезателни условия.

### 8. Как реализирате персонализирана помощна функция, базирана на Promise (например механизъм за повторен опит) за React приложение?

```jsx
const retry = (fn, retries = 3, delay = 1000) =>
  fn().catch((err) => {
    if (retries === 0) throw err;
    return new Promise((res) => setTimeout(res, delay)).then(() =>
      retry(fn, retries - 1, delay)
    );
  });
```

### 9. Как подхождате към управлението на микрозадачи и макрозадачи в React приложение с интензивни асинхронни операции?

- **Микрозадачи**: Promise-и, `queueMicrotask`.
- **Макрозадачи**: `setTimeout`, `fetch`.

Използвайте **микрозадачи за свързване на логика във верига**, а **макрозадачи за отлагане** на изпълнението.

### 10. Как използвате протокола за асинхронна итерация (например `for await...of`) в React приложение за поточно предаване на данни?

Използва се за **API за поточно предаване** (например SSE, части от файл):

```
async function streamData(url) {
  const response = await fetch(url);
  for await (const chunk of response.body) {
    processChunk(chunk);
  }
}
```

В React:

- Изпълнявайте вътре в `useEffect`.
- Полезно е за **потоци в реално време или продължителни изтегляния**.

### 11. Как използвате ES модулите в голяма React кодова база, за да осигурите поддръжка и tree-shaking?

- Използвайте **именувани експорти** за по-добър tree-shaking.
- Структурирайте функционалностите в **изолирани папки** с `index.ts` за barrel exports.
- Избягвайте експорти по подразбиране в споделени библиотеки, за да **подпомогнете статичния анализ**.

### 12. Как разбирате обхвата и повдигането на декларациите в JavaScript и как предотвратявате често срещани проблеми в React?

**Отговор:**

- **Обхват**: лексикален — определя се при писане на кода.
- **Повдигане на декларациите (hoisting)**: `var` и декларациите на функции се повдигат.

В React:

- Използвайте `let`/`const`, за да избегнете проблеми с hoisting.
- Не разчитайте на повдигнати променливи в затварянията или hooks.
- Декларирайте променливите **в обхвата на hook-а/компонента**.

### 14. Как прилагате принципите на функционалното програмиране (например неизменяемост и чисти функции) в React приложение?

- Използвайте `map`, `filter` и `reduce` за преобразуване на данни.
- Не променяйте състоянието директно (например използвайте оператори за разширяване).
- Извличайте **чисти помощни функции** за селектори и бизнес логика.
- Библиотеки: Lodash/fp, Ramda (когато е необходимо).

### 15. Как подхождате към мемоизирането на скъпи изчисления в JavaScript за React приложение?

Използвайте `useMemo`:

`const filtered = useMemo(() => heavyFilter(data), [data]);`

Избягвайте преждевременната оптимизация; първо профилирайте. Уверете се, че зависимостите са правилни, за да избегнете остарели или повторно изчислени стойности.

### 16. Как оптимизирате производителността на JavaScript в React приложение, като намалявате мутациите на обекти?

- Използвайте **неизменяеми актуализации** (например оператори за разширяване, `immer`).
- Избягвайте сортиране на място или добавяне към масиви с `push`.
- Това помага на React да открива промените чрез **плитко сравнение** (`React.memo`, `PureComponent`).

### 17. Как използвате JavaScript Proxies или Reflect в React приложение за динамично управление на състоянието или отстраняване на грешки?

Използвайте `Proxy`, за да проследявате мутациите или да създавате обвивки, подобни на реактивни:

```jsx
const state = new Proxy(
  {},
  {
    set(target, key, value) {
      console.log(`${key} changed to ${value}`);
      target[key] = value;
      return true;
    },
  }
);
```

Полезно е за **отстраняване на грешки**, **библиотеки за формуляри** или **персонализирани observable обекти**.

### 18. Какво знаете за събирането на боклука в JavaScript и как предотвратявате изтичането на памет в React приложение?

JS използва **събиране на боклука чрез маркиране и обхождане (mark-and-sweep GC)**. Изтичането на памет възниква, когато обектите останат неволно реферирани.

В React:

- **Почиствайте** в `useEffect`.
- Избягвайте остарели препратки или задържане на DOM възли в затваряния.
- Наблюдавайте изтичанията чрез раздела Memory в Chrome DevTools.

### 19. Как се справяте с проблемите с точността на числата с плаваща запетая в JavaScript (например при финансови изчисления) в React приложение?

Избягвайте вградените числа с плаваща запетая за пари. Използвайте:

- **`Intl.NumberFormat`** за показване.
- **Big.js**, **decimal.js** или `BigInt` за аритметика.

### 20. Как подхождате към добавянето на polyfill или shim за съвременни функции на JavaScript в по-стари браузъри за React приложение?

- Използвайте **Babel + core-js** за транспилиране/полифили.
- Използвайте конфигурацията **browserslist**, за да зададете целевите браузъри.
- За ключови функции (например `fetch`, `Promise`) използвайте условни polyfill-и или динамични импорти.
