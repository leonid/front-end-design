### 1. Как си представяте Document Object Model (DOM) на HTML и връзката му с Virtual DOM на React?

**DOM** е живото дървовидно представяне на HTML документа в браузъра. Директната му промяна е скъпа заради преизчисляването на оформлението и повторното изчертаване.

React въвежда **Virtual DOM (VDOM)** като олекотено представяне на DOM в паметта. При промяна на състоянието:

- React изчислява **разликите** между предишното и следващото VDOM дърво.
- Той **обединява и свежда до минимум** операциите върху реалния DOM чрез процеса на съгласуване (reconciliation).

```jsx
useState triggers re-render → VDOM diff → minimal DOM updates
```

Този модел подобрява производителността и позволява декларативни потребителски интерфейси.

### 2. Какъв е мисловният ви модел за структуриране на семантичен HTML в компонентна рамка като React?

Семантиката трябва да насочва структурата дори в рамките на компонентите. Свързвам **ролите и предназначението** с подходящи тагове (`<nav>`, `<main>`, `<section>`, `<article>`).

Пример:

```jsx
function BlogPost({ title, content }) {
  return (
    <article>
      <h2>{title}</h2>
      <section>{content}</section>
    </article>
  );
}
```

Избягвам излишно вложени `div` елементи, като третирам компонентите като семантични обвивки и използвам HTML5 тагове, когато е възможно. Това подобрява достъпността и SEO.

### 3. Как разбирате взаимодействието между HTML атрибутите (напр. `data-*`, `aria-*`) и props в React?

React третира стандартните HTML атрибути и специалните атрибути (`aria-*`, `data-*`) като **props, предавани към DOM възела**.

```jsx
<button aria-label="Close" data-testid="close-btn">
  X
</button>
```

- `data-*`: за тестване, анализи или куки за поведение.
- `aria-*`: за достъпност (поддръжка на екранни четци).
- И двата вида са **пълноправни елементи** в JSX и трябва да се използват целенасочено.

### 4. Как бихте проектирали HTML структура за сложен, вложен потребителски интерфейс (напр. многостепенно навигационно меню), така че да остане лесен за поддръжка?

Подход:

- Използвайте семантични тагове: `<nav>`, `<ul>`, `<li>` и ARIA роли, ако са необходими.
- Изобразявайте вложените данни рекурсивно.
- Поддържайте компонентите атомарни.

```jsx
function NavItem({ label, children }) {
  return (
    <li>
      {label}
      {children && <ul>{children.map(...</ul>}
    </li>
  );
}
```

Разделям отговорностите (напр. представяне и логика) и осигурявам навигация с клавиатура и достъпност.

### 5. Как подхождате към моделирането на HTML формуляри в приложение на React, особено по отношение на валидирането и изпращането?

Използвам **контролирани компоненти** за предвидимо състояние:

```jsx
const [email, setEmail] = useState("");
<input value={email} onChange={(e) => setEmail(e.target.value)} />;
```

За валидиране:

- Използвайте **Yup/Zod** + **React Hook Form** или собствена логика.
- Валидирайте директно при загуба на фокус или при промяна.
- Предотвратявайте действието по подразбиране при изпращане и обработвайте асинхронните действия безопасно.

```jsx
<form onSubmit={handleSubmit(onSubmit)} />
```

### 6. Как преценявате влиянието на HTML парсването и изобразяването върху производителността при зареждане на страницата?

**Критичният път на изобразяване** се влияе от:

- **Размер на HTML**: по-голям DOM означава по-бавно парсване и изобразяване.
- **Блокиращи ресурси**: синхронните скриптове забавят парсването на DOM.
- **Дълбочина на DOM**: дълбоките дървета увеличават сложността на оформлението и преизчисляването му.

Оптимизирам чрез:

- Намаляване на първоначалния HTML обем (напр. отложено зареждане на некритични части от интерфейса).
- Подреждане на съдържанието по приоритет (съдържанието над сгъвката).
- Използване на SSR/Streaming за подобряване на времето до първия байт.

### 7. Какъв е мисловният ви модел за обработване на HTML събития в приложение на React в сравнение с обикновен JavaScript?

В React:

- Събитията са **синтетични**: обвити са за съвместимост между браузърите.
- Те се разпространяват нагоре като нативните събития, но чрез системата на React за делегиране на събития (в кореновия елемент).

```jsx
<button onClick={handleClick}>Click me</button>
```

Предимства:

- Последователно поведение.
- По-лесно управление на паметта.
- Обединяване на актуализациите.

В обикновен JavaScript:

- Добавяте слушатели директно към елементите.
- Почистването трябва да се извършва ръчно.

React опростява жизнения цикъл и подобрява производителността.

### 8. Как проектирате HTML структури, които поддържат progressive enhancement в приложение, базирано на React?

Създавам HTML, който работи **първо без JavaScript**, а след това го надграждам с React.

Пример:

- Изобразете SSR HTML с работещи връзки и бутони.
- Хидратирайте го от страна на клиента за по-богато взаимодействие (напр. модални прозорци, търсене).

Използвайте:

- Семантичен HTML
- Резервни съобщения в `<noscript>`
- Подход с приоритет на достъпността (навигация с клавиатура, видим фокус)

```html
<button type="submit">Search</button>
```

След хидратирането надграждането добавя филтри, анимации и др.

### 9. Как разбирате ролята на HTML в приложение на React, изобразявано от страната на сървъра (SSR)?

В SSR HTML е **първоначалното изобразяване**, което се изпраща към браузъра:

- Подобрява **Time to First Paint (TTFP)** и SEO.
- React хидратира HTML до работещо приложение.

Моят модел:

- Поддържам маркировката семантична и минимална за SSR.
- Използвам тагове в `<head>` за метаданни, заглавие и предварително зареждане (чрез `react-helmet` или `@vitejs/plugin-react`).
- Избягвам недетерминистично изобразяване (напр. `window`, `localStorage` на сървъра).

### 10. Какъв е мисловният ви модел за управление на HTML метаданни (напр. `<meta>`, `<link>`) в едностранично приложение (SPA)?

Третирам метаданните като част от **контекста на динамичния маршрут**. За SPA:

- Използвам `react-helmet` или `@tanstack/router`, за да задавам декларативно `<title>`, `<meta>` и др.
- При промяна на маршрута актуализирам head за SEO и споделяне в социалните мрежи.

```jsx
<Helmet>
  <title>Product Page</title>
  <meta name="description" content="Details about product" />
</Helmet>
```

За PWA управлявам също `<link rel="manifest">`, икони и подсказки за предварително зареждане.
